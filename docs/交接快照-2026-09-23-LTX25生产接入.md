## 2. 怎么用（用户面）

1. **平台 → 生成引擎配置 → 出片相关区块 → 「出片引擎」**：`Wan2.2 I2V（480p·16fps，旧，默认）` / `LTX-2.5（1280×704·24fps，新）` → 保存即对新任务生效。
2. 镜头弹窗现在**会显示当前出片引擎**，并按引擎算「需要帧数 = 镜头时长 × 原生 fps」（wan22=16、ltx25=24）。
3. 服务器 env 也能兜底（优先级：**UI 配置 > env**）：`/etc/weaveora/weaveora-gpu-worker.env` 的 `WEAVEORA_MOTION_ENGINE=wan22|ltx25`（现为 `ltx25`）。

### LTX 相关开关（都在 `/etc/weaveora/weaveora-gpu-worker.env`）
| 变量 | 缺省 | 作用 |
|---|---|---|
| `WEAVEORA_MOTION_ENGINE` | `wan22` | 引擎默认值（UI 未配时生效；**线上现设为 `ltx25`**） |
| `WEAVEORA_LTX25_MAX_SIDE` | 1280 | 出片长边上限（LTX 官方可到 4K，我们按 48G 卡定 1280） |
| `WEAVEORA_LTX25_KEEP_AUDIO` | 0 | LTX 自带音轨是否保留（默认剥掉，交付用 TTS 音轨） |
| `WEAVEORA_LTX25_FPS_X2` | 0 | **时间轴 ×2**（24→48fps，走 `ltx25_i2v_48fps_api.json`）—— 代码已写、**待部署**（见 §5） |
| `WEAVEORA_LTX25_TIMEOUT` | 1800 | 单镜超时（秒） |
| `WEAVEORA_VIDEO_MOTION_FRAMES_MAX` | 121 | **平台帧数上限**（API 侧 env）：LTX 下 121 帧 = 5.04s |

## 3. 实测数字（2026-09-23，盒上 `48G 4090`）

| 场景 | 帧数/时长 | 耗时 | 峰值显存 | 结果 |
|---|---|---|---|---|
| 官方样张裸跑 1280×704 | 121 帧 / 5.04s | **145.65s** | 44,662 MiB / 46,068（97%） | 成功（含音轨） |
| **生产端到端**（含 `/free` 等显存回落 + 模型载入 + 串行排队） | 121 帧 / 5.04s | **≈200s** | 同上 | **succeeded**（DB 实查） |
| 8s 长镜 | 193 帧 / 8.04s | 到 170.9s 时被打断 | **45,080 MiB（98%）** | **不推荐**：采样已跑完但显存贴边，随后被生产任务清队列打断 |
| 输出规格 | — | — | — | 1280×704 / **24fps** / H.264 + AAC 音轨；`_strip_audio` 后交付无音轨 |

**结论**：**帧数上限维持 121**（= LTX 5.04s / Wan 7.56s）。8s 不建议开（98% 显存 + 单卡只能串行）。
**排期口径**：LTX 一镜 ≈ **3.5 分钟**（5s 镜头、720p、单卡独占）。

## 4. 本次踩到/修掉的坑

1. **worker 在 VPS 本机读工作流 JSON**，而 `deploy/comfy/*.json` 以前靠手工 cp → 有人在盒上放了新工作流、忘了同步 VPS ⇒ 任务报
   `LTX-2.5 工作流不可读（…/ltx25_i2v_api.json）：No such file or directory`（用户两个 clip 任务因此 failed，重跑即可）。
   已修：`deploy/vps-worker-deploy.sh` 增加「`deploy/comfy/*.json` 只补齐缺失、不覆盖」同步（有意不一致的线上工作流不会被洗掉）。
2. **下载器会把文件预分配到满尺寸** ⇒ 用"文件大小"判完成会把半成品误判为完成（本次先误判过一次）。判据一律改看 `.done`。
3. **ComfyUI `SaveVideo` 的历史记录写在 `images` 键下**（不是 `videos`），`_download_outputs` 原本就能取到；本次只加了 `videos/gifs` 兜底。
4. **官方 LTX-2.5 模板默认开「提示词增强」**（需另下 `gemma4_e2b_it_int8_convrot`，ModelScope 无此 int8 版）→ 摊平后**摘掉了这条支路**，正词直连。
5. **`ResizeImageMaskNode` 的动态控件在 API 里的键名是 `resize_type.longer_size`**（带点，不是 `longer_size`）—— 实测探到的。
6. **不要按节点类名丢 `PrimitiveBoolean`**：`LTXVImgToVideoInplace.bypass` 还引用它（363=Switch to Text to Video?）。
7. **VPS 是 Python 3.6**：`subprocess.run(capture_output=True)` 不可用（需 3.7+）→ 一律 `stdout/stderr=PIPE`。
8. **单卡串行**：LTX 峰值 97% 显存 ⇒ 跑出片时不能并行跑对口型/talk；worker 跑前会自动 `POST /free`（`_free_comfy_models`）。
9. 手工往 ComfyUI 投测试任务会被 worker 的「清孤儿队列」打断（`_clear_orphan_prompts`）——**生产优先，属预期行为**；做基准要在队列空闲时跑。
