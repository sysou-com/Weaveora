## 3. 第三轮：提纲持久化 + 分集字数

| 项 | 做法 |
|---|---|
| **提纲持久化（V18）** | `scripts.outlines jsonb`（key=要素）、`script_episodes.outline jsonb`；「AI 更新」在**段数与目标一致**时直接复用（省一次调用、结构不漂），弹窗可勾「重新生成写作提纲」；分集提纲随集保存、重开可见 |
| **分集字数可调** | `AiNextEpisodeRequest.targetChars`（>8000→400）；「开始下一集」弹层内嵌同一套字数控件（抽成 `ScriptLengthField.vue` 共用），分集与要素各记一份 localStorage |
| **写超自动压缩** | 模型管不住长度（目标 1500 实测写出 2692）→ 封顶与目标挂钩（≈目标×1.3，夹到 [800,2600]）+ 写超 >1.5× 时做**一次压缩重写**（保留人物/冲突/关键事件/**结尾钩子**），实测 **2692 → 1607**；无论成败写进 `note`；压缩失败保留原稿 |
| **单段分集修正** | `plan.passes()==1` 时本段功能从「起」改为「起→承转→合一次写完、必须在字数上限内收束」（之前只让它「起」、它却按整集写，是超字主因） |

**验收 9/9**：提纲首生 2 段（55s）→ GET 回传已持久化 → 第二次**复用**（日志命中、提纲逐字一致）→

分集目标 1500 → **1607 字**（自动压缩 2692→1607）→ targetChars=9000 → 400 →
分集提纲随集保存（GET episodes 回传）。

⚠️ **碰过的坑（记一下）**：一次多编辑调用是**全部成功才生效**；当其中一处 oldText 不匹配时**整批回滚**，

## 4. 第二轮（A/B/C）：字数弹窗 + 输入预算 + 提纲先行 + 全剧记忆

用户追问「每个要素这么长，生成详情时会不会失败？现在怎么处理？要不要分段/大纲？」→ 实测后一次做完：

**实测（直打 DeepSeek，非推测）**：1 汉字 ≈ 1 token（2 万字→20030 prompt_tokens）；**30 万 token 输入不报错**
→ 上下文 ≥30 万，**超长不会失败**；真正的代价是成本/延迟膨胀 + 「中间丢失」的隐性质量下降。

| 项 | 做法 |
|---|---|
| **字数弹窗** | 点 AI 生成/更新（含一键全部）**先弹窗设目标字数**：500–8000（滑块+预设，记住上次）；后端 `targetChars` `@Max(8000)` 校验 + `clampTarget`；段数由目标算（`planFor`） |
| **A 输入预算** | `ScriptPrompts.context()`：目标字段全文 + 其它要素「头60%+尾40%」摘要（≤1200/项）+ 每集标题摘要全量 + **仅最近 2 集正文**；总量封顶 **12000 字**；裁剪记 INFO 日志 |
| **B 提纲先行** | 先生成与段数 1:1 的提纲（每段 2–4 个要点），再「第 K 段只写提纲第 K 条」；提纲回前端展示（字段 diff 弹层 / 分集抽屉）；提纲失败不阻断正文 |
| **C 全剧记忆** | 「精简的故事」（≤1500）作为最高优先级上下文注入**所有**调用（字段/分集/一致性/引导），空则显式写「尚无」 |

**验收 7/7**：

| 项 | 实测 |
|---|---|
| targetChars=9000 | **400**（上限 8000 生效） |
| 目标 1200 | 实际 **1329 字**、提纲 1 段、**19s** |
| 目标 8000 | 实际 **8925 字**、提纲 4 段、**96s**（比第一轮 4000 字的 135s 更快——上下文变小了） |
| `from_content`（5×8000 字要素） | 实际 1585 字、提纲 1 段、15s；**日志出现裁剪记录**（故事/情节/语言/舞台说明→982 字，冲突为目标字段保留全文） |
| `next-episode` | **6821 字**、提纲 2 段、164s |
| 裁剪日志 | 2 条 `上下文已按预算裁剪（12000 字上限）…` |

## 5. 第一轮：上线后暴露的 3 个坑（已修；改这块先读）

1. **一次要「≥4000 字」必被 `max_tokens=8000` 截断**（`finish_reason=length` → 网关重试两次 → 422，实测 92s）。
   已改为**分段续写**：每段约 2200 字、提示词硬上限 2600、最多 3 段，拼接后达标；续写段注入**前文尾部 1400 字** +
   「不得重复」+「不要总结」+「不要在本段把整集收尾」。常规两段（≈4400 字）即满足 ≥4000。
   - 代价：字段约 90～135s、一集约 90s → 前端已提示「1–2 分钟请勿关页」；「一键生成全部」改**并发 3 路**（串行要十几分钟）。
   - nginx `/weaveora/api/` 已是 `proxy_read_timeout 1800s`，无需改。
2. **模型把 JSON 字符串写出真实换行** → `readTree` 报 `Unexpected character ('豪'): was expecting comma…` → 两次尝试全废。
   已在网关（剥围栏后、校验前）加 `infra/llm/JsonGuard.repairStrings()` 修复字符串内裸控制字符；
   真结构损坏（少括号）仍会失败，不掩盖真问题。单测 `JsonGuardTest` 8 例。
3. **返回键名不能只认一个**：模型偶尔把正文放在 `text`/`body`/`value` 或子对象里；早期只读 `content` 得空串 →
   抛 BizException 且**无任何日志**（排障只能猜）。已加 `ScriptAiService.pickText()` 多键回退（含 `正文/内容`）+
   失败日志带**顶层字段名 + 原文开头 320 字**；提示词也统一成固定结构（每段都返回 title/summary/content）。

另配套韧性：**某段失败/返回空正文时不丢已生成部分** —— `retryBlank()` 先明确要求「必须给正文」重试一次，
仍失败则保留已有内容并在结果 `note` 里如实告知「未达 4000 字，可重试或手写补全」（不静默）。
