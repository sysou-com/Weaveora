## 2. A2Vid（LTX-2.5 音频驱动出片）—— **建议先 0 下载验证**

### 2.1 依据（本地官方模板 + 本地节点源码，均已核实）
- 官方模板 `.../comfyui_workflow_templates_json/templates/video_ltx2_3_ia2v.json` 的音频链是：
  ```
  LoadAudio → TrimAudioDuration(0, duration) → LTXVAudioVAEEncode(audio, audio_vae)
            → SetLatentNoiseMask(samples=↑, mask=SolidMask{value=0,w=1024,h=1024})   ← ★关键
            → LTXVConcatAVLatent(video_latent, audio_latent=↑冻结)
  ```
- 机制（`comfy_extras/nodes_lt.py` 的 `LTXVConcatAVLatent`）：AV 联合 latent 带 **`noise_mask`**；
  mask=0 的部分**不参与去噪**（= 冻结）。`LTXVAudioVAEEncode` 继承 `VAEEncodeAudio`，**不带 mask**
  ⇒ 少了 `SetLatentNoiseMask` 那一步，音频就会跟视频一起被从 sigma=1.0 重去噪（= 模型自己重生成语音）。
- 两段 sigma 排程与我们 2.5 i2v **逐字相同**（`1.0,0.99375,…,0.0` / `0.85,0.7250,0.4219,0.0`）。

### 2.2 实测记录（2026-09-23，同一关键帧/正词/尺寸/种子）
| 方案 | 耗时 | 峰值显存 | 帧 | 输出音轨 vs 输入配音（包络相关） |
|---|---|---|---|---|
| 空音频（现役基线） | 169.3s | 43.8 GiB | 97 | 0.228（无关，模型自生成） |
| 配音 latent（**无** mask） | 131.1s | 43.8 GiB | 97 | 0.068（无关）→ 说明"只编码"没用 |
| 配音 latent + **noise_mask=0 冻结**（= A2Vid 式） | **204.4s** | **42.8 GiB** | 97 | **0.934 @ 时移 0ms ⇒ 音轨就是我们的配音** ✅ |

### 2.2.1 验证结论（2026-09-23，**最终判定：不出口型**）
1. **音轨**：输出音轨与输入配音包络相关 **0.934、最佳时移 0ms**（基线 0.228 / 不冻结 0.068）⇒ 配音被**原样保留**；
2. **嘴部运动 vs 音频包络**（客观）：A（自生成音轨）0.414 / B（我们配音）0.407 —— 两个版本嘴都在跟着音轨动，
   该指标**分辨不出**"嘴型是否对上我们的台词"（只能证明"在动"）；
3. **LLM 逐帧目视**（`deploy/diag/ask_image.py` 看对照图）：A 六帧**以闭合/微张为主、未见明显张开**；
   B 六帧呈"闭合 → 微张 → **明显张开（t=1.4）** → 闭合"的变化 ⇒ **B 更接近"在说话"**。
- ❌ **最终判定（用户 2026-09-23 亲眼看片）：未看到口型** —— 音频确实进去了（相关 0.934），
  但**画面嘴部不跟随我们的台词**。⇒ 只冻结音频 latent 不够；官方 ia2v 另有 **dev 主干 + distilled LoRA
  + 音频驱动 LoRA**（这正是它要那批权重的原因）。
  **纪律**：这一条属"看起来接线对了、指标也漂亮，但功能没实现"——**指标（音轨相关）不能代替功能验收（口型）**。
- ⚠️ 我那次测试用的音频是一段**遗留 TTS wav**（`weaveora_lipsync_125b23e5_voice.wav`，来自 09-22 某次对口型），
  很可能就是**第 5 镜**的台词（用户听出来了）—— 测试素材选得不严谨，与产品行为无关。
- 对照物已发（临时公网，可随时删）：
  `https://sysou.com/weaveora/_p7/` 下 `A_无配音_LTX自生成音轨.mp4` / `B_A2Vid_用我们配音.mp4` / `口型对照_A上B下.png`
- 代价：**204.4s / 42.8 GiB**（与空音频基线 235.9s / 42.7 GiB 相当，**不额外涨显存**）。

## 4. 图片模型可切换 —— 候选与文件

### 4.1 ★ 推荐：**FLUX.2 [klein] 4B**（Apache-2.0）
| 文件 | 体积 | 放哪 |
|---|---|---|
| `flux-2-klein-4b.safetensors`（单文件；或 `transformer/diffusion_pytorch_model.safetensors`） | 7.75 GB | `models/diffusion_models/` |
| `text_encoder/model-0000{1,2}-of-00002.safetensors` | 4.97 + 3.08 GB | `models/text_encoders/`（需确认 ComfyUI 的加载方式） |
| `vae/diffusion_pytorch_model.safetensors` | 0.17 GB | `models/vae/` |
| 小计 | **≈16.0 GB** | |
- 能力（官方/模型卡）：**文生图 + 图生图 + 多参考图编辑**；4B 参数；约 **13 GB 显存**可跑；**Apache-2.0（可商用）**。
- 另有 `FLUX.2-klein-base-4B`（**未**做步数/引导蒸馏，质量更高但更慢）——同样 23.7 GB 仓内文件，按需二选一。
- 风险：属"速度档"模型（我们 09-22 的 FLUX2 评估已记）；多人一致性能否胜过 Qwen-Image-Edit-2511 **必须 A/B 才知道**。

### 4.2 现役与已排除
| 模型 | 许可 | 结论 |
|---|---|---|
| **Qwen-Image-Edit-2511**（现役） | **Apache-2.0**（可商用） | 不需要换；仍是"多参考图编辑"最强可商用档之一 |
| LTX-2.5 文生图/图生图 | — | **不存在**（官方只有 t2v/i2v/flf2v；2.3 才有 ia2v/ic_lora/id_lora） |
| Seedream | 闭源 | 只能走 API（与 §0-2「GPU 推理不自己盒上」冲突） |

### 4.3 「图片模型」切换机制（代码侧，可与下载并行做）
照「出片引擎」的三处成对做法：
1. 后端 `EngineSettingsService` 增图片引擎白名单键（如 `image.variant` / `model` / `workflow` / `editWorkflow` / `steps` / `cfg` / `denoise`）；
2. worker `comfy_client` 按 variant 分派工作流与档位（`IMAGE_VARIANT`）；
3. 引擎页「图片生成引擎」区块加下拉：`Qwen-Image-Edit-2511（现役）` / `FLUX.2 klein 4B` / …
> ⚠️ 新增配置项必须**三处同时改**，否则就是四段坑 3 那种"UI 配了没效果"的静默失效。
