## 3. 出图档位（当前配置，配置页可改，代码不写死）

```
services.image = {
  engine: comfy,
  workflow:         /opt/weaveora/workflows/qwen_image_txt2img_film_api.json   (2512)
  img2imgWorkflow:  ""            ← 不用 img2img（会把定妆照白底带过来）
  editWorkflow:     /opt/weaveora/workflows/qwen_image_edit_api.json          (2511, 官方结构)
  steps: 20, cfg: 2.5, denoise: 1.0
}
```
- Edit 工作流是**官方结构**：`TextEncodeQwenImageEditPlus`（prompt+参考图同时输入）+ **主参考图 `VAEEncode` 作采样起点**；**不要加 resize 节点**（节点内部会把参考图缩到 ~1MP）。
- **不装 Lightning LoRA**（用户要求：不为速度牺牲细节）。
- 实测：1280×704 / 20 步 ≈ 采样 4.4 s/步；缓存策略 `--cache-ram 32`（曾用 `--cache-none` 导致每张重载 20G+CPU fp8 转换，已修）。

## 4. 位置（路线 A 生效；两层位置 + 主体点名）

**两层位置**（后端 `JobService.applyLayoutRegions`，优先级从高到低）：

| 层 | 数据 | UI | 语义 |
|---|---|---|---|
| ① 逐镜 | `shots[].layout = [{subject,x,y,w,h}]` | 分镜卡展开 → 「画面位置（本镜）」（可拖拽 + w/h 缩放 + ±1% 微调） | **本镜**位置/远近（w/h 越大=越近） |
| ② 方案级 | `referenceAssets[].region` / `subjects[].refs[].region` | 方案页右卡「位置预览（相对位置 / 区域%）」 | **全片默认**位置（逐镜未覆盖时生效） |
| ③ 点选 | `shots[].lipsync_targets = {subject:{x,y}}` | 预览图点选人脸 | 只有点 → 默认框 0.30×0.45 |

- 归一化 0–1（相对画面宽高），`w/h` 表达**远近与大小**。
- 后端把它们写进 `referenceRegions`（与 `referenceKeys` 同序）**并拼进正词**：
  `Reference image mapping: image1 = 宝玉 (upper-left, x=0.19, y=0.09, box 0.30x0.45); image2 = 可卿 (...)`。
- **`image1` = `referenceKeys[0]`**（= `qwen_image_edit_api.json` 里 LoadImage 节点 `12`，节点按 id 字符串排序取图；`14` = `image2`）。改工作流勿打乱 LoadImage id 顺序。
- **槽位上限 = 2**：Edit 工作流只接了两个 LoadImage 槽，第 3 个主体不报错但图会被默默丢掉（要 3 主体先加节点 + 接 `image3`）；某张参考图上传失败时槽位会前移一格。
- **即使没设任何位置，也照样写「imageN = 主体名」**（只点名、无坐标）—— 这是「positive_prompt 必须点名主体」的后端兜底，不依赖 LLM。无 subject 名的风格参考图不点名。
- **路线 B（区域条件）代码保留但默认关闭**：`WEAVEORA_IMAGE_AREA_COND=1` 启用；它在 Qwen-Image-Edit 的参考图 conditioning 上会让 KSampler 抛 `IndexError: tuple index out of range`（两轮实测），需离线找出成立写法（候选：挂在纯 CLIPTextEncode 基础 conditioning 上 / `ConditioningSetArea` 像素口径 / 分主体各自 Edit 再合成 / 2511 原生 ControlNet 几何）。
- 单测：`api/src/test/java/studio/weaveora/job/JobLayoutRegionsTest.java`（8 例：三档优先级、兜底点名、非法框丢弃、无锚定不动正词）。

## 6. 重要纪律（血泪）

- **重启任何 GPU 服务必须走 `bash deploy/gpu2_restart.sh`**（先查库，有 queued/running 就拦；`FORCE=1` 才强推）。绝不在有任务时重启 —— 曾把用户 21:49 的对口型任务撞死（502 Cannot connect to host 127.0.0.1:8001）。

- spark 式排障顺序：先看 `/queue`（是否僵尸 prompt）→ 再看 worker 日志 → 再看 ComfyUI 日志（**过滤 `non matching host` 噪声**）。
