```
修复前 盒  /opt/weaveora/workflows/flux2_dev_edit_api.json   13/16/19 = ImageScale(lanczos, 1664×928, crop=disabled)  md5 19ad8684…

```
- **生产不走盒上那份**：worker 在 VPS 上、`WEAVEORA_IMAGE_EDIT_WORKFLOW=/opt/weaveora/workflows/flux2_dev_edit_api.json`
  读的是 VPS 本地件（`_wf_load()` 开本地文件）。
  ⚠️ 更正第一版的写法：VPS 件与仓库件**内容逐节点一致、字节不同**
  （规范化 JSON 的 md5 两边都是 `1319cbddc0463ee953f896afac06e392`；差异只在缩进/序列化，3978 vs 4066 B），
  所以部署脚本报的「md5 不一致」是**格式差异**，不是内容差异。19:04 那条任务下发的就是这份 1MP 内容。
- 但盒上那份**是个雷**：定妆照是 1:1（1344×1344），`ImageScale(width=1664,height=928,crop=disabled)` = 横向 ×1.78、
  纵向 ×0.69 —— **脸被拉扁**。今天 C 臂实测：三张脸 cos 全 ≤0.27、脸高只占画面 6–7%。
  任何盒侧 diag / 将来的切换脚本 / 手工试枪只要指到它，就会「图出得来但脸全错，且不报错」。

### 4.2 ✅ 槽位改写不幂等：正词里有 `Reference Reference Image N`（已修）

`_flux2_slot_rewrite` 的三条规则原本**分三次 `sub`**，第三条 `_FLUX2_SLOT_RE_IMG`（`(?<![A-Za-z])image\s*(\d+)`）
会**把上一步刚写好的 `Reference Image 1` 再吃一遍**（`Image` 前是空格，负向环视放行）：
```
Picture 1 (image1)  --RE_PIC-->  Reference Image 1  --RE_IMG-->  Reference Reference Image 1
```
19:04 的 `finalPrompt` 实测：`Reference Reference Image 1/2/3` 各 1 次（共 3 次），前缀那段是干净的。
文档 §0.7.2 只修了「前缀被二次改写」这一半，这半（**改写产物被自己二次改写**）漏了。

## 9. ★★ 方案 2 实测：逐脸「单参考重绘 + 羽化贴回」—— **有效，旋钮是 denoise**

> 2026-09-25 13:30–13:45，用户裁定「试方案 2」。盒 180.127.11.167:21220（新实例，up 2min，clean）。
> 素材：第 4 镜 12:50 那张关键帧（三张脸修复前 cos = -0.003 / 0.170 / 0.206，argmax 全指向警幻）。
> 脚本：`/opt/weaveora/diag/wv_facefix.py`（新增，盒上跑）+ `wv_facefix_sweep.py`（denoise 扫描）。

### 9.1 做法

```
关键帧 → insightface 检脸 → 以脸为中心裁方形（边长 = 2×脸框长边）→ 放大到 1024×1024
      → ComfyUI：底图 = 该裁切（SplitSigmasDenoise denoise=d）+ ReferenceLatent = 该角色定妆照（**单参考**）
      → 出图缩回裁切尺寸 → 羽化椭圆贴回原图（**只换脸上那一块像素，构图/站位/背景一格不动**）
```

工作流是脚本内联拼的「生产 img2img 图 + 一条 ReferenceLatent 支链」（20 步 / guidance 4 / euler / 参考缩到 1MP）。

### 9.2 结果（cos 在**最终 1664 图**上量，与历史数据同口径）

| 脸（左→右） | 认领 | 修复前 | dn=0.55 | **dn=0.75** | **dn=0.90** |
|---|---|---|---|---|---|
| #1 x=0.26 宝玉 | 宝玉 | -0.003 | 0.186 | **0.593** ✅ | **0.754** ✅ |
| #2 x=0.55 可卿 | 可卿 | 0.170 | 0.263 | **0.341** | **0.707** ✅ |
| #3 x=0.70 警幻 | 警幻 | 0.206 | 0.292 | **0.370** | **0.501** ✅ |
| 自己的脸是否 argmax | — | ❌（全指警幻） | ❌ | **✅ 三张都是** | **✅ 三张都是** |
| 脸宽（px） | — | 67/72/85 | 65/72/83 | 82/81/98 | 114/94/113 |

**同一张脸（宝玉）在 1024px 重绘图上的 denoise 扫描**（sweep，最能说明问题）：

| 版本 | 宝玉 cos |
|---|---|
| 输入裁切放大后（模型看到的底图，未重绘） | **-0.029** |
| denoise 0.55 | 0.190 |
| denoise 0.75 | **0.535** |
| denoise 0.90 | **0.758** |

### 9.3 结论

1. **方案 2 成立**：三张脸全部变好，dn=0.90 时**三人全部 >0.5** 且每张脸自己的 cos 都是最高（"谁是谁"分得开）——这正是"脸型错乱"要修的东西。
2. **关键旋钮不是画幅，是 denoise**：0.55 保留 45% 的原像素，而那 45% 恰恰是"没有身份"的那部分 ⇒ 只提升到 0.19；0.75 起效、0.90 基本按参考重画脸。
3. **成本**：1024px、3 张脸 = 54–66s/脸 ⇒ **单张关键帧 +3~4 分钟**。比"整图提到 2560"（时间 ×2.37 ≈ 10 分钟、且只把脸线性放大 1.54×）**便宜得多、效果更彻底**。
4. 重绘时那张脸在 1024 canvas 上 ≈512px（比定妆照自己的脸 394px 还大）⇒ 身份有像素可用。
5. **只改脸，不改站位**：身体/构图/背景一格未动。若站位本身错了，本方案不负责（那是构图/控制问题）。
6. ⚠️ 待用户肉眼判定：dn=0.9 是"重画脸"（表情/发型/脸型可能变）、羽化贴回的接缝、以及"身体位置是不是那个角色"（本方案按**显式站位**贴脸，原图脸太小无法自动认领）。

## 10. ★★ 方案 1-C 概念验证：「构图底图」通路（2026-09-25 晚）

用户裁定「先试方案1的C」。假设：身份弱的直接原因是**脸占画面太小**（生产 7–9% 帧高），
而文字管不了构图 ⇒ 用**图像**控几何、用参考控身份、文字只管动作/环境。

脚本 `deploy/diag/wv_layout_base.py`（盒上跑）：把"主脸角色"的定妆照仿射到 1664×928 画布，
令其**脸正好**落在指定位置且**占帧高 face-ratio**（默认 0.22 = 生产的 2 倍）→ 当 img2img 底图
（`SplitSigmasDenoise`）+ 1–2 条 `ReferenceLatent` 串链。

### 10.1 结果

| 臂 | 配置 | 检出脸 | 主脸占帧高 | 主脸身份（最高 cos） |
|---|---|---|---|---|
| A0（生产基线） | 3 参考 + 中景 + 纯噪声 | 3 | 7–9% | 0.126 / 0.110 / 0.293 |
| **C0** | **只改正词口径**（过肩 + 「主脸约占帧高 1/5」），底图被忽略（dn=1.0） | 3 | **29.8%** | 宝玉 0.452 |
| C1 | 底图(可卿) + 1 参考(宝玉)、dn 0.70 | 1 | 21.9% | 宝玉 0.44 |
| C2 | 底图 + 2 参考(宝玉/警幻)、dn 0.70 | 1 | 21.5% | **警幻 0.555 ✅** |
| C3 | 底图 + 2 参考、dn 0.85 | 2 | 20.5% | **宝玉 0.533 ✅** |

### 10.2 三个结论

1. **几何可控（实证）**：底图把主脸精确钉在目标位置/大小（目标 22% → 实测 21.5–21.9%，落点 x=0.62）。
   **而且只改提示词口径也能到 29.8%**（C0，底图都没用上）⇒ 「量化构图句」是有效的，零成本。
2. **身份随几何改善**：主脸到 20% 档就出现两个**过线**结果（0.555 / 0.533），而生产 7–9% 档从未过 0.35
   —— 与 §1.2 的回归（cos ≈ −0.0012+0.00441×脸宽px，r=0.722）**量级吻合**。
3. **「3 人一帧」被证否**：脸一放大就装不下第三人（C1/C2 只检出 1 张脸、C3 只有 2 张）。
   更关键：**"底图那个人"与"参考图那些人"会互相抢身份** —— C1 底图是**可卿**，输出的大脸却读成
   **宝玉 0.44**（可卿 0.342）；C2 大脸读成警幻 0.555；C3 读成宝玉 0.533。
   ⇒ 模型**没有"身份槽"**，所有输入图会被揉进同一条 conditioning；谁是"主角"由不得我们。

### 10.3 落地形态（由上面数据直接推出）

- **多人镜拆成 1–2 人/帧**：主脸 22% + 3 人**几何上互斥**（不是调参能解决的）；
- **构图底图 + 量化构图口径**是真杠杆（脸 8% → 21–30%，身份随之过线）；
- **确需 3 人同框**时才上**专用身份通道**（方案 2：insightface `inswapper` 类换脸权重 / 或 Qwen-Image-Edit 定身份）—— 待 GPU 侧授权。
