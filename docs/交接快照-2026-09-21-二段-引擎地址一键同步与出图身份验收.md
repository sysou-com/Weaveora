## 3. 本轮最关键的实测结论（写文档/排障请直接引用）

### 3.1 「第 4 镜少了一个人 / 警幻占了可卿的位置」——用身份匹配查清了
工具：`build/diag/wv_faceid.py`（GPU 盒上跑，`/opt/weaveora/ComfyUI/venv/bin/python`）。
**cos 口径**：>0.5 同一人；0.35–0.5 偏弱可疑；<0.3 基本不是同一人。

| 版本 | 检出脸 | 身份判定 |
|---|---|---|
| 旧 09-20 23:35 | **2** | 可卿 0.642 ✅、宝玉 0.53 ✅ |
| 新 09-21 08:52 | 3 | 宝玉 0.60 ✅、可卿 0.317 ⚠、第 3 张 56px **不像任何人**(0.10) |
| 新 09-21 09:02（用户说"刚跑完"） | 3 | 宝玉 0.587 ✅、可卿 0.417 ✅、**第 3 张最像可卿 0.384** ⚠ |

**结论**：**`image3` 的「警幻」在三个版本里从未出现**（对她最高 cos 仅 0.13–0.18）；
09:02 那版第 3 张脸最像**可卿** → 视觉上就是"**画了两个可卿**"。且**这与正词简化无关**（09-20 旧版同样只画出 2 个人）。
三张定妆照彼此**不是同一人**（宝玉-可卿 0.074 / 可卿-警幻 0.144 / 宝玉-警幻 0.218）→ 不是定妆照重复。
站位也偏中间：宝玉 x=0.39（清单要求 0.17）、可卿 0.66（要求 0.50）。

**排除项（都核对过，别重复查）**：payload `referenceKeys` 3 张、`referenceSubjects=[宝玉,可卿,警幻]`；
worker 日志 `Picture 1/2/3` 一一对应；线上 `qwen_image_edit_api.json` 与仓库**同 md5** 且有 `image1..image3` 三槽；
`service→asset→storage` 三条绑定链一致（`portraitAssetId` → storage key）。

### 3.2 「Connection refused → 参考图上传失败」有**两种指纹**，别混
- `comfy POST /upload/image -> 502 b"edge proxy: upstream error: Cannot connect to host 127.0.0.1:8001"` = **网关活着、盒内 ComfyUI 没起**（跑 `services_up.sh`）；
- 裸 `<urlopen error [Errno 111] Connection refused>` = **TCP 都没连上**（地址/端口已失效）——`comfy_client._comfy()` 只捕 `HTTPError`，连接被拒是 `URLError`，不被包装。

### 3.3 还有两个"静默"行为要记住
- **放大失败会静默保留原图**：worker 日志 `[comfy] WARN 出图放大失败（保留原图）：…`（本轮 10:20:42 就发生过一次——盒失联时正好在放大）。
- **`assets.width/height` 记的是放大前尺寸**（DB 里始终 1664×928，磁盘文件其实是 3328×1856）→ 资产卡显示的数字**不是**成片尺寸。**未修**（待办 §5-3）。

### 3.4 日志"服务地址"会骗人（再次确认）
`[comfy] 服务地址：comfy=<COMFY>` 打的是 `services.lipsync.comfyUrl`；而出图/参考图上传走的是
`IMAGE_COMFY = services.image.comfyUrl`。两者不一致时日志会显示"已经对了"而实际打到别处（09-21 07:2x 那次 4 连败的真因）。
