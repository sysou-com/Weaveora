## 5. 显存 / 内存 / 速度账

### 5.1 硬件实况（2026-09-22 实测）

| 项 | 值 | 备注 |

| RAM | **47 GiB**（`free -m` total 48168 MB） | ⚠️ **与 `GPU服务器能力搭建指南.md §1.1` 写的 62 GB 不一致** —— 换盒后本实例就是 47 GiB，**这是本次最大硬件风险** |

| 其它常驻 | tts 8091 / face 8093 / talk 8094 等 | 与出图共用 RAM |

### 5.2 FLUX.2 dev 的账（**推算，非实测**）

- **VRAM**：主模型 33.0 + 编码器 11.4 = **44.4 GiB / 47.4 GiB**（93.7%）。二者**不可能**同时常驻还要留 VAE + 激活 ⇒ 依赖 ComfyUI 的"先编码后卸载编码器"路径（v0.4.0 起有专门的 Flux2 TE 卸载/去量化记账修复）。**结论：能跑，但踩线，必须实测。**
- **RAM**：33 GB 主模型从盘上按层流式载入（safetensors mmap），配合 `--cache-ram 8` 不至于把 47 GiB 打爆，但换页会显著拖慢首帧。
- **速度**：dev 是 32B 且**非步数蒸馏**（官方模板 20 步 + guidance 4）。
  - 有利面：latent 16× → 1664×928 只有 **6032 token**（比 Qwen-Image 的 8× 便宜 4 倍），高分辨率不是瓶颈。
  - 不利面：参数量 20B→32B，且没实测。
  - **不要凭推算给承诺**：下完必须跑一次 benchmark（见 §7-P2 第 4 步），指标 = `单张 1664×928 耗时` + `峰值显存` + `是否换页`。
- **降载手段（按优先级）**：① fp4 文本编码器 ② 出图前重启 ComfyUI 拿干净 RAM ③ Turbo LoRA 8 步档 ④ klein 4B 替代。

## 7. 落地方案（三段式，先便宜的后贵的）

### P0 —— 0 成本，先做（与换模型无关，但可能是"能力不行"的真因）
四段 §4.3 已定位、**至今未改**的两条：
1. 项目风格前缀 `cinematic` → 改 `photography`（「电影质感」前缀把图拉成插画感）；
2. 定妆照模板：白底 + 柔和均匀光 + 无 realism 正词、负词缺 `illustration/cartoon/plastic skin`。
> 换模型不会自动修掉这两条；**先修它们，再谈"模型能力不足"才公平**。

### P1 —— klein 4B（Apache-2.0，11–15 GiB，可商用）当"通路验证机"
1. 下 3 件（klein 4B + `qwen_3_4b_fp4_flux2` + `flux2-vae`）；
2. 在盒上按官方模板 `image_flux2_klein_image_edit_4b_distilled.json` 改一份**我们自己的** API 格式工作流，落到 `/opt/weaveora/workflows/flux2_klein_{txt2img,edit}_api.json`；
3. `worker/comfy_client.py` 加 **flux2 注入分支**（见下）；env 指向新工作流（`WEAVEORA_IMAGE_WORKFLOW` / `_IMG2IMG_` / `_EDIT_`），**保留 Qwen 文件与旧 env 备份**；
4. A/B 同一批 prompt + 同一参考图（定妆照 1 张 + 关键帧 2 张），逐字节对照 `md5(positive_prompt)`，比"像不像真人 / 参考图遵从度 / 文字渲染"；
5. 结论若"明显不如 2511" → 直接停在这里，省掉 45 GB 和许可风险。

### P2 —— dev 32B（**前置条件：拿到 BFL 商业授权 + 腾足空间**）
1. 腾空间（§4.3 走后确认流程）或接受"只留 6.4 GiB 余量"；
2. 下载 1+2+3（44.77 GiB，后台化 + 断点续传，进度只落日志）；

### 7.2 必须知道的"能力退化"（换之前要想清楚）
1. **负词失效**（蒸馏引导）→ 我们整套"负词驱动"的提示词资产要改写；
