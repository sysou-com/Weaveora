## 4. 本段最重要的实测结论

### 4.1 对口型「嘴部乱码」：**上段的"半幅回贴"结论作废**（绿框画错坐标系）

上段（四段之后的会话）用绿框 bbox 判出「锁定/回贴区域 = 左半幅 = 位置总控构图框」⇒ 推出「贴回半个画面 ⇒ 乱码」。**本段读源码后证伪**：

- `deploy/latentsync-node/files/latentsync/utils/image_processor.py:147-149`
  ```python
  face, affine_matrix = self.restorer.align_warp_face(image.copy(), landmarks3=landmarks3, smooth=True)
  box = [0, 0, face.shape[1], face.shape[0]]   # ← 左上角恒为 (0,0)，边长 = 对齐裁剪的尺寸
  ```
- `…/pipelines/lipsync_pipeline.py:_debug_mark(frame, box, …)` 直接把 `box` 当**原帧坐标**画框。
- ⇒ 绿框**画在了裁剪坐标系**（永远从画面左上角起画），它的右/下边缘只编码「裁剪图有多大」，**与脸在哪、与回贴区域都无关**。
  上段实测 `x 0.000–0.505 / y 0.000–0.996`（832×464 下 ≈ 420×462 px）正好符合"锚在 (0,0) 的裁剪尺寸"。
- **因此：拿"框在不在嘴上"判 H1 是无效的**（这也是我要求"先把框修对"的原因，§2-2）。真正的回贴是 `restore_img(原帧, face, affine_matrix)`，走仿射逆变换 + 羽化掩码，**不是矩形覆盖半幅**。
  > 注：本结论基于**仓库里的节点补丁源码**；盒子下线，无法回读线上副本（`apply.sh` 应保证一致）。

### 4.2 「视频上限 3.75s」= 前端算错（不是真上限）

`ProjectDetailView.modelCapEffective` 用**项目成片帧率**除帧上限 → 32fps 下 `121/32 = 3.78s`；真实口径是 **121 帧 ÷ 原生 16fps = 7.56s**（后端 `maxClipSec` 一直是对的）。危害不止显示：按 3.75 去填帧数（60 帧）→ 模型只生成 3.75s 内容 → 导出用 `tpad=stop_mode=clone` 克隆尾帧补满 → **尾部静止**。
**公式（别再按"秒 × 成片帧率"算）**：`实际帧数 < 镜头时长 × 16` 就会出现尾部静止；导出那步 `fps=` 也会用**复制帧**拉齐 → 顿挫。已修：优先用后端 `maxClipSec`，`VideoLimits` 补 `nativeFps`。

### 4.3 帧率口径（本段定死）

- 原生生成 = **16fps**；交付 = **32fps = 16×2**（RIFE ×2）。**必须是原生帧率的整数倍**：`FrameInterpolate.multiplier` 只收整数 2–16，整数倍才能等分插入得到均匀时间轴；旧的 `30fps`（1.875×）既插不了帧、又要被导出阶段用复制帧拉齐 → 顿挫。
- 12:08 线上实测：`motion dual preset=hero steps=20(switch 10) cfg=3.5/3.5 shift=8.0 832x464 80帧 lora 0/0` → `插帧：RIFE ×2` → 产物 `832×464 / 32fps / 160 帧 / 5.000s`（`ffprobe` 复核，无降帧、无 tpad）。

### 4.5 motion 正词/档案注入口径（易误解，已定死）

- **档案注入范围**：定妆照 = **全档案**（`describe(true)`：性别/年龄/身高/体态/性格/外貌·服饰）；**关键帧 / motion = 只 性别·年龄**（`describeRef`）。
- **motion 正词不再写人物信息**（视频通路根本没有参考图，写"以参考图为准"指向不存在的图）：只留「以关键帧为构图基准」+ 动作/朝向/运镜口径；主体名仅进日志（`motionNames`）。
- **单帧镜的 `positive_prompt` 必须按「出图口径」写**（一个场景句子），**不得**写成只有运动+运镜的句子 —— 这是「两张并排上身像 / 不体现剧情」的源头之一（字段与模板对应硬规则已写进两份模板）。

## 5. 坑（本段新增，均已实测）

1. **`api-deploy.sh:83` 用 `[ -x ]` 判断旧 jar ⇒ 备份静默不执行**（线上 jar 是 `0644`、没有 x 位）→ **09-15 之后的所有 API 部署都没有 jar 回滚点**（`ls /opt/weaveora/api/*.bak.*` 只到 09-14），而脚本仍会打印一条指向**不存在文件**的「回滚」命令。本段已改成 `[ -f ]`（护栏只对**下次**部署生效，旧包找不回来）。
2. **工作流 JSON 在"仓库 vs 线上"不一致**：仓库 `deploy/comfy/qwen_image_edit_api.json` = **带 2511 节点**（`9279c93f…`），线上 = 无节点回滚版（`61f3fb47…`）。**没有任何脚本会自动同步 `deploy/comfy/*` 到 VPS**（都是手工 cp）→ 谁手工推一次仓库版就把致病因带回来。`services.image.*Workflow` 读的是 **VPS 上的文件**，ComfyUI 只在 GPU 盒上跑图。
3. **调试画框坐标系**（§4.1）：节点里 `box = [0,0,crop_w,crop_h]` 被当成原帧坐标画 → 任何"框住谁/框在哪"的目视判断都是错的。要看脸在哪，得用仿射逆变换把裁剪四角映射回原帧再取 bbox。
4. **DB `services.lipsync.workflow` 值末尾带空格**：`"/opt/weaveora/lipsync_workflow_api.json "` —— 目前不影响（worker 侧 `.strip()`/拼接容忍），但属"看着像路径、其实不是"的隐患，改配置时顺手清掉。
5. **worker env 改动没留备份**：13:09 加 `WEAVEORA_LIPSYNC_DEBUG_BOX=1` 时没有 `.bak`（`/root/weaveora-backups/` 里最新的 env 备份是 09-21）。回滚方式：**删掉那一行 + `systemctl restart weaveora-gpu-worker`**。
6. **手写脚本直连 `POST /prompt` 必须删掉工作流 JSON 顶层的 `_comment`**，否则 ComfyUI 返回 aiohttp 默认 500 纯文本「Server got itself in trouble」（本次冒烟测试就这么被误导过；worker 的 `_wf_load()` 本来就会 pop 掉，业务不受影响）。
7. **`/system_stats` 的 `torch_vram_*` 不可信**（§4.4），判显存用 `nvidia-smi` + `mem_get_info()`。
8. **别把"端口能连"当"是我们的盒子"**：同一 IP 后面可能挂不同主机；身份只能由 **域名/登录串 + `argv[0]` + 权重清单** 双重确认；**同镜像的主机键不变**，不能拿它判"是不是同一台"。
9. **脚本里任何"安全闸/备份"都必须实测它真的跑了**：本段两个静默空转（`vps-worker-deploy.sh` 的 SSH 数组顺序、`api-deploy.sh` 的 `-x`）都属于"闸门看起来在、其实从没生效"。做法：修完**打印它到底拦到了什么**（如"本次 0 running"）。
10. **同机双会话**：本机（`Invisible`）可能另有 pi 会话 ⇒ `~/.ssh/config`、`known_hosts`、DB/env **只能一个 writer**；交接只传「路径 + hash + 3 行结论」。
