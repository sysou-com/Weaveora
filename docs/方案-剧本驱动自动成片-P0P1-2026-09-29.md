## 0. 一句话

把「用户只关注剧本」做成可执行链路：**系统按当前引擎能力（GPU／云 API）+ 台词/旁白时长确定性拆镜**，
用户依次点「确定/下一步」走完 定妆照 → 关键帧 → 运动 → 配音配乐 → 成片。
LLM 不再负责算时间，只负责语义（分镜内容、台词、配乐策略）。

## 3. 架构

```
L1 剧本解析（已有 to-project）      Episode → 项目 + 分镜
L2 时长规划（新）                   台词时长（真实配音优先/文本估算）+ EngineCaps → 每镜时长 + segments
L3 制作流程编排（新）                portraits → keyframes → motion → audio → render，一键「确定」
L4 执行（复用）                      job / worker / ComfyUI / audio / ConcatService
```

### 3.1 `ShotTimingPlanner`（纯函数，`studio.weaveora.director.plan`）

- 有台词镜：`时长 = 台词时长 + 0.3s 余量`；无台词镜：沿用导演目标时长，夹在 `[minShot, cap]`。
- 超引擎上限：按 `oversize_policy` —— **默认 `stretch`**：只生成 1 段（按上限帧数），成片阶段本地重定时拉伸；
  `segment` 切成多段；`overflow` 配音顺排溢出。
- **总长归一**：与项目目标的差额**只补给无台词镜**（呼吸），绝不压缩台词；补不满时在 `notes` 如实说明。
- `applyTo(plan)` 写回 `shots[].duration_sec / segments[] / stretch` 与
  `edit_plan.timing_mode=audio_first / oversize_policy / video_model_max_sec / tail_sec`。

### 3.2 引擎能力契约 `EngineSettingsService.videoCaps(userId, plan)`

`maxShotSec = 帧数上限 ÷ 原生帧率`（GPU 用 `motion-frames-max`，云用 `motion-frames-max-cloud` 或项目 `video_model_max_sec`）。
**GPU 与云 API 走同一契约**，二期云 API 接入时调用方不用改。返回 `maxShotSec / nativeFps / deliverFps / motionEngine / route / maxFrames`。

### 3.3 校验器 `DirectorPlanValidator`

- 单镜上限改为**按引擎能力**（重载带 `maxShotSec`）。
- **按 `segments[]` 逐段校验**：stretch 策略下镜头总时长可以超过上限（生成时按上限出一段、成片本地重定时）。

### 3.4 制作流程 `ProductionRunService`（`studio.weaveora.job`）

- 阶段：`portraits → keyframes → motion → audio → render`。
- **各阶段完成度由已有 `generation_jobs` + `assets` 派生**（不另做会卡死的 saga）；只把**用户的确认动作**落库
  （V20 `production_stage_approvals`），满足 §0-3。
- 门禁写死在代码：关键帧需人物主体已定妆；运动需关键帧齐；配音需运动齐；成片需运动+配音齐。
- 阶段「确定」= 批量下发**缺失项**（幂等）：关键帧/运动按缺的 `shot_no`；配音按缺的 `(shotId, lineIndex)`；
  配乐仅当无 bgm 资产；成片调 `ConcatService.renderMaster`。

### 3.5 P1：自动台词 / 音色 / 配乐

- `prepare`：按人物性别自动分配内置音色（男→中文男、女→中文女）→ 台词缺失时按剧情生成（≤16 镜，LLM）→ 重排时长。
- 台词时长：**优先用已生成配音的真实时长**（`assets.prompt_snapshot.line_index` + `duration_ms`），
  缺失段按文本估算（中文 4.5 字/秒、英文 13 字符/秒）；段间 0.25s。
- `MusicCuePlanner`：逐镜 `music = none|bed|hit` → 配乐段落；**`none` 镜不铺配乐**（用户口径「不一定每镜都要配乐」）。
  连续同策略合成一段；`hit` 同 mood 但音量更高（不另生成曲子，省成本）。
- 导演 video system prompt 增第 ⑧ 条：逐镜给 `music`。

## 4. API 端点（新增）

```
GET  /api/v1/projects/{id}/runs/status?revisionId=       制作流程总览（只读）
POST /api/v1/projects/{id}/runs/replan                   只重排时长（确定性、不跑 LLM；前端打开页面自动调）
POST /api/v1/projects/{id}/runs/prepare                  自动音色 + 自动台词 + 重排时长（{revisionId, lines}）
POST /api/v1/projects/{id}/runs/stages/{stage}/confirm   点「确定/下一步」→ 记录确认 + 批量下发
POST /api/v1/projects/{id}/runs/stages/{stage}/retry     重试该阶段失败任务
```

## 5. 数据模型（V20 `V20__production_stage.sql`）

```sql
production_stage_approvals(id, project_id, workspace_id, revision_id, stage,
                           approved_by, approved_at, note,
                           UNIQUE(project_id, revision_id, stage))
```

## 8. 部署后验收清单（P0/P1）

1. **迁移**：`ssh ... "sudo -u postgres psql -d weaveora -c '\d production_stage_approvals'"`；API 健康 UP（Flyway validate 过）。
2. **能力契约**：视频项目页 `GET /runs/status` 返回 `maxShotSec`（LTX 应 ≈5.04、Wan ≈7.56）与 `nativeFps`。
3. **自动拆镜**：打开一个已确认的视频项目（未优化过）→ 面板自动 `/replan` → 镜长合计 ≈ 目标、单镜 ≤ 上限、

4. **一键流程**：人物主体存在时点「确定」→ 生成定妆照 → 绑定 → 关键帧 → 运动 → 配音/配乐 → 成片，每步一个按钮。
5. **配乐按需**：方案里给某镜标 `music: none` → `/prepare` 后 `audio.music[]` 在该段无 cue（混音听起来该段无 BGM）。
6. **幂等**：同一阶段连点两次「确定」，不产生重复任务（同 `(shotId,lineIndex)` / `shot_no` 已有资产则跳过）。

## 9. 已知边界（有意不做 / 待后续）

- **旁白自动生成**：`AiAudioService` P12 口径下 AI 只写角色对白，旁白仍需手动加（本方案未改该口径；问题 4 的「旁白驱动拆镜」已生效 —— 手动加的旁白会计入时长）。
- **每帧关键帧计数**：阶段完成度按「每镜至少 1 张 still」算，多帧运镜的逐帧细表仍在原分镜台。
- **云 API 单段 4/6/8s**：`videoCaps` 已支持，但需二期云适配器把模型 `duration` 映射进 `video_model_max_sec`。
- **`timing_mode` 兼容**：老方案仍是 `shot_fixed`，只有跑过 `/replan` 或 `/prepare` 才变 `audio_first`（不静默改历史项目）。
- **自动 `/replan` 会写服务端方案**：只改时长/分段/配乐/音色绑定，不改分镜文案；前端 unsaved 草稿不会被覆盖（`initKey` 按 revisionNo 判定）。
