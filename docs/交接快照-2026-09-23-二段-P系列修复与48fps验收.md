## 4. 本场新增的坑（4 条）

1. **官方模板摊平出来的工作流可能有节点类型不匹配**，且**只有真 POST `/prompt` 才会暴露**（`/object_info` 看不出）：
   `ltx25_i2v_48fps_api.json` 的 `CreateVideo.fps` 收 FLOAT，模板给的是 `PrimitiveInt`（节点 902）⇒
   `HTTP 400 prompt_outputs_failed_validation / return_type_mismatch`。**24fps 版之所以没事**：它走
   `ComfyMathExpression(359)` 中转，输出是 FLOAT。⇒ 新工作流一律"先 POST 试一枪"（返回 400 就是校验失败，不会开始跑）。
2. **`WEAVEORA_LTX25_FPS_X2=1` 之前是 100% 必失败**（因为上面那条）—— 上一场"代码已写、待部署/待实测"的真实阻塞点在工作流，不在开关。
3. **`.done` 与实体文件是两件独立的东西**：实体被删后 `.done` 会留下（看着像"已下载"）⇒
   判定"权重在不在"**必须看实体文件**，`.done` 只能当"上次完整下载过"的提示。
4. **两台机器上的同名工作流 md5 不同 ≠ 内容不同**：`ltx25_i2v_api.json` 仓库 `f1b6c137…` vs 线上 `c4beb044…`，
   规范化 JSON 后 md5 **完全相同**（只是缩进/键序不同）⇒ 比对工作流要**规范化后再比**，别拿文件 md5 判漂移
   （`vps-worker-deploy.sh` 对这种"有意不一致"只报警不覆盖，是对的）。
