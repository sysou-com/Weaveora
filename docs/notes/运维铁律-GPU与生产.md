# 运维铁律（GPU / 生产 / 部署）

> 来源：本机记忆沉淀 `consol_convention.txt`（2026-09-16 迁入仓库）。原始来源=历次真实事故复盘，**每条都对应一次踩坑**。
> 涉及 GPU 地址/端口的部分**一律以平台「生成引擎配置」页为准**，本文里的端口只是当时的快照。

[convention] Weaveora 剧本/引擎口径补：①**引擎不在线只提示、不拦生成**（2026-09-17 用户裁定）：GPU 掉线时用户还要继续处理分镜动作/提示词，提交出图任务应当**照常入队**（`JobService.logEngineOfflineIfAny` 只记日志），前端用 `GET /api/v1/engine/status`（`gpuOnline/cloudOnline/notice`）在项目页顶部弹黄色提示条；**禁止**把「无在线节点」做成 503 拦掉（前一天做成硬拦，被用户否掉）。②判定口径单一：`JobService.nodeServes(lane, capabilities)` + `nodeAlive(lastSeenAt, now)`（5min 宽限，与任务回收同一口径），历史 `stub-cpu` 节点不算任何车道。③剧本「集→项目」关联 = `briefs.constraints.scriptEpisodeId`；再次转项目默认**同一项目出 V+1**（不新建），`newProject=true` 才另建。④剧本保存只写库（sync=false，~0.1s），「精简的故事」刷新+一致性检查走**后台** `/ai/condensed`（实测 3.7–70s，且必须在事务外）。

[convention] Weaveora 运维铁律：①配置/地址单一入口（用户反复强调）：GPU 公网 IP/端口禁止写死进代码/配置/脚本/文档；唯一权威=平台「生成引擎配置→GPU服务器地址+端口」保存即下发 worker（推导 ComfyUI <gpu>:8001、配音/转写 <gpu>/audio、整脸口型 <gpu>/talk、人脸 <gpu>；同容器可电信+移动两入口，端口同 IP [convention] Weaveora 提示词语言与帧数上限口径（2026-09-17 晚，实测）：①**提示词语言是项目级**（`plan.promptLang` + `briefs.constraints.promptLang`）：转项目弹层选 中文(默认)/English，导演**首次生成**就按它输出，项目页「AI 更新提示词」默认语言也读它；②中文覆盖**必须追加到系统词末尾**（`DirectorService.PROMPT_LANG_ZH_OVERRIDE`）—— 只挂 user 消息实测**无效**（模型仍输出英文，因 `director_video_system.md` 里「prompt 字段用英文」出现多次，权重更高）；③「帧数上限 → 秒数」要用**模型原生帧率**（`weaveora.video.motion-native-fps:16`，A14B=16），**不能**除以 `edit_plan.fps(30)`：本机 `motion-frames-max=121` 帧的真实单次上限 = 121/16 = **7.56s**，而旧口径 `maxClipSec = 121/30 = 4.03s`（偏低 → 会让「按配音校准」多切段、多花 GPU）。我新增 `motionLimits.maxClipSecNative` 供**提示**使用（未改旧口径，是否统一待用户拍板）；④转项目时若镜头时长超过该上限，响应 note 会明说「有 N 个镜头超过当前引擎单次上限 X s，会自动切段生成」。
