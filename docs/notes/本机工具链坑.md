[tool-quirk] 跨项目工具链坑（含本机 wanglg/Git Bash）：①中文在 GBK 控制台乱码→输出 ASCII 或重定向 utf-8 文件再读；psql/python 读含中文文件必须显式 utf-8。②Maven 大构建 malloc failed（多因 VSCode redhat.java 驻留）→MAVEN_OPTS 限堆或杀残留 java；Git Bash 无 make→export JAVA_HOME 后直接 mvn。③各工具 /tmp 互不相通（pi write=%LOCALAPPDATA%\Temp、Git Bash /tmp=D:\tmp\x、Docker 另处）→跨工具传文件用绝对路径+项目内 .scratch/ 并各自 ls 验证。④ctx_batch 默认 PowerShell 吞 && 与引号→探库/远端改 bash+SQL 文件。⑤`cd A B` 多词路径未引号报 too many arguments；rg 反斜杠/多文件 glob 报 OS error 3/2→逐文件 rg 或 grep -F；bash 中文 grep 参数须引号。⑥core.autocrlf=true 使工作区变 LF，与 Linux 比 md5 前先去 CR；本机无 sshpass/plink，免密只靠已有凭据。⑦GitHub 直连不可靠→VPS clone --mirror→git bundle create --all→scp 回本地→git fetch <bundle> 'refs/heads/*:refs/remotes/origin/*'（HTTP/1.1）。⑧pi-hermes-memory：failures.md 上限=memoryCharLimit×2（默认10000字符，含元数据）；replace/remove 按子串匹配整条整体替换，replace content 须自带 [tag]（不自动补），保留 created/project 且 last 置今天；切勿并行 remove/add 同一文件（曾截断0字节）→串行+先备份；含凭据内容被 threat pattern 拦截；pi-web-access jiti ENOENT 改用 raw.githubusercontent.com/cdn.jsdelivr.net。
## 追加 · 2026-09-24：`sleep_hours.ps1` 睡不下去（Windows PowerShell 5.1 的编码雷）

**现象**：`deploy/windows/sleep_hours.ps1 19` 通过计划任务执行 → `LastTaskResult=1`、机器根本没睡；日志里是
`ParserError: 字符串缺少终止符: "`，且报错行把**注释行和下一行 `Write-Host` 粘在了一起**（`# 4) 进入睡眠（…）Write-Host "--- 进入睡眠 ---"`）。

**根因**：该文件曾是 **UTF-8 无 BOM + LF**。**Windows PowerShell 5.1 对无 BOM 的 `.ps1` 按 ANSI/GBK 解码** →
中文注释的 UTF-8 字节被误读，其中有些字节序列会被解析器当成引号/续行符 ⇒ 整个脚本**一行都没执行**。

**处置**：把文件转成 **UTF-8 with BOM + CRLF**（`file` 应显示 `UTF-8 (with BOM) text, with CRLF`）。
改完先做**只解析不执行**的验证（否则一跑就睡）：
```powershell
powershell -NoProfile -Command "try { [void][scriptblock]::Create((Get-Content -Raw -Encoding UTF8 'D:\workspace\Weaveora\deploy\windows\sleep_hours.ps1')); 'PARSE OK' } catch { 'PARSE FAIL: ' + $_.Exception.Message }"
```

**通用教训**：仓库里凡是**会被 Windows PowerShell 直接执行**且**含中文**的 `.ps1`，一律存成 **UTF-8 with BOM**；
否则本机跑得动（Git Bash/utf-8 视角）、PowerShell 一跑就炸，而且表现为"任务成功调度但脚本零执行"。
（对比：`.cmd`/`.bat` 走的是 OEM 代码页，含中文同样有风险 ⇒ 首选 ASCII 或改走 Git Bash/Python 脚本。）

**调度作业本身的坑（也记一下）**：
- `schtasks` 在 Git Bash 里会被 MSYS 路径转换搞坏参数（`/query` → `C:/Program Files/Git/query`）；`//query` 又不被接受。
  ⇒ 改用 PowerShell 的 `New-ScheduledTask*`/`Register-ScheduledTask`（写成 `.ps1` 文件再 `-File` 跑，避免内联引号地狱）。
- 后台保活：本机 Git Bash 里 `nohup … &` 与 `cmd /c start` **都活不过工具调用结束**（进程随组被回收）——
  要"等 N 分钟后自己跑"，必须走**计划任务**（实测 `Register-ScheduledTask` 可靠）。
