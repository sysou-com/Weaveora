## 3. ★ 本会话定位到的致命 bug（已修复、已冒烟；但**在跑的进程仍是旧代码**）

**现象**：`sync` 跑到 `[14/88]` 就不动，日志反复刷同一句：
```
dd: failed to open 'models/loras/Wan_2_2_I2V_A14B_LOW_lightx2v_4step_lora_260412_rank_64_fp16.safetensors': No such file or directory
[14/88] … 0.0%  0 B/601.5 MiB  0 KiB/s     （分片重试 29 次）
```
**根因**：大文件分片通道的 `dd` 用的是**相对远端根的路径**，却**没有 `cd` 到远端根**（`fetchSegment`，约 666 行）。
小文件通道是对的（`tar -C ${sq(CFG.remote)}`）→ 所以**小文件能到、大文件全废**，而这个进程会一直空转重试。
**实测复现**（30 秒可自证）：
```bash
ssh gpu "nice -n5 ionice -c3 dd if='models/loras/Wan_2_2_I2V_A14B_LOW_lightx2v_4step_lora_260412_rank_64_fp16.safetensors' bs=1048576 iflag=skip_bytes,count_bytes skip=0 count=1024 status=none 2>&1 | wc -c"
#   → 134（错误输出，失败）
ssh gpu "cd /opt/weaveora && nice -n5 ionice -c3 dd if='models/loras/Wan_2_2_I2V_A14B_LOW_lightx2v_4step_lora_260412_rank_64_fp16.safetensors' bs=1048576 iflag=skip_bytes,count_bytes skip=0 count=1024 status=none 2>/dev/null | wc -c"
#   → 1024（成功）
```
**修复**（已在文件里）：`const core = \`cd ${sq(CFG.remote)} && dd if=… \``
**冒烟验证**（已通过）：单文件 `sync --apply --detach --only '^audio/CosyVoice/pretrained_models/CosyVoice2-0.5B/hift\.pt$'` → `bigDone 1/1`、83 MB、`fail 0` ✓

> ⚠️ **必须重启同步进程才生效**：PID 223496 是 18:38 启动的，内存里是旧代码。

## 6. 验收标准（怎么算"同步完了"）

1. `status --state "$S"` 的 `phase` = `sync-done`，`fail: 0`；
2. `plan.txt` 里 `## 需要传输` 变成 `0 个文件 / 0 B`（missing/truncated/oversize 全为 0）；
3. `G:\ComfyUI\weaveora` 的 `du` 与远端 `/opt/weaveora` 的 `du` 相当（允许软链/`.done` 差异）；
4. 抽样：随便挑 3 个大权重，比对**字节数**（本地 = 远端）+ 远端 `sha256sum` 与本地（`--deep` 时）；
5. 软链：`symlinks.tsv` 里 internal 的那几条，在本地用 `restore_symlinks.sh` 可重建。
