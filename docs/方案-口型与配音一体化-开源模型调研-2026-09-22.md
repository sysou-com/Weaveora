## 0. 直接回答

| 问题 | 答案 |
|---|---|
| **口型能并进视频模型吗？** | ✅ **能，而且盒子已经装好了**：ComfyUI 原生节点 `WanSoundImageToVideo(+Extend)`、`WanInfiniteTalkToVideo`、`WanHuMoImageToVideo` 都在，**官方模板**（`video_wan2_2_14B_s2v.json` / `video_wan2_1_infinitetalk.json` / `video_humo.json`）也随包装好了 ⇒ **不用装任何自定义节点**，LipsSync（LatentSync）整段链路可以下线。 |
| **配音也能并进同一个模型吗？** | 🟡 **只有"联合音视频生成"模型能自己出声**（代表：**LTX-2.3**，22B，开放权重，一次生成视频 + 同步音轨）。**但它念的不是你写的台词**（语音是按提示词"编"出来的，音色/台词不可精确控制）⇒ **做剧集对白不适用**。工程上**"配音"仍应留给 TTS**（本机已部署 CosyVoice2，Apache-2.0，是整条链里最便宜、最稳的一环）。 |
| **720p 慢能解决吗？** | ✅ **能省掉两次模型串联**。现状 = `关键帧 → Wan I2V 480p(16fps) → LatentSync → RIFE×2(32fps)`；换成 S2V/InfiniteTalk/HuMo = `首帧图 + 音轨 → 一次过模型`，口型内生；**InfiniteTalk / HuMo 原生 25fps** ⇒ **RIFE 也能省**。720p：S2V 与 InfiniteTalk 官方均支持 480P/720P，**48G 卡上的耗时要实测**（无公开口径）。 |

**推荐顺序**：① **Wan2.2-S2V-14B**（最省：只需下 15.86 GiB，u mt5/VAE 已有）→ ② **InfiniteTalk**（多角色对白 + 25fps）→ ③ **HuMo**（唱歌/表演）→ ④ **LTX-2.3**（探索项，不进生产）。

## 2. 盒子可行性（2026-09-22 实测）

### 2.1 软件：全部就绪，**零自定义节点**

`/object_info` 实测存在（盒子 ComfyUI **v0.34.0**）：

```
WanSoundImageToVideo / WanSoundImageToVideoExtend      ← Wan2.2-S2V（音频驱动）
WanInfiniteTalkToVideo                                 ← InfiniteTalk（多人对白/配音重制）
WanHuMoImageToVideo                                    ← HuMo（说话/唱歌）
AudioEncoderLoader / AudioEncoderEncode                ← wav2vec2 / whisper 音频编码器
LTXVAudioVAELoader/Encode/Decode, LTXVConcatAVLatent,
LTXVSeparateAVLatent, LTXVReferenceAudio, LTXVModalityGuidance   ← LTX-2 音视频联合（核心）
```
`custom_nodes/` 里只有 `ComfyUI-LatentSyncWrapper` ⇒ 上面这些**都是核心节点**（`comfy_extras/nodes_wan.py`、`nodes_lt.py`、`nodes_lt_audio.py`）。

配套官方模板（已随 `comfyui_workflow_templates_json 0.1.57` 落地）：
`video_wan2_2_14B_s2v.json`、`video_wan2_1_infinitetalk.json`、`video_humo.json`、`video_ltx2_3_ia2v.json`（+ ltx2_3 i2v/t2v/flf2v/ic_lora…）。

### 2.2 官方模板的关键参数（照抄即用）

| 模板 | 关键设置 |
|---|---|
| **S2V** | `WanSoundImageToVideo(640, 640, 77, 1)`；chunk **77 帧**（模型最少 73 帧，≈4.8s@16fps）；每加一个 **Video S2V Extend** 子图 +77 帧；`ModelSamplingSD3 shift=8`；`uni_pc/simple`；步数 **20**（挂 `wan2.2_t2v_lightx2v_4steps_lora_v1.1_high_noise` 时 **4 步**）；`CreateVideo fps=16`；正/负词照 Wan 惯例（负词现成中文串） |
| **InfiniteTalk** | 832×480、**81 帧（3.24s@25fps）**、`CreateVideo fps=25`、lightx2v I2V distill LoRA、双角色各自 **MaskEditor 掩码** + 各自音轨（`LoadAudio` ×2 + `AudioConcat`） |
| **HuMo** | `WanHuMoImageToVideo(640, 640, 97, 1)`、`CreateVideo fps=25`、音频编码器 `whisper_large_v3_fp16`、6 步档 |

## 3. 三个落地方案

### P1（推荐先做）· Wan2.2-S2V 取代「Wan I2V + LatentSync」

```
现状：关键帧 → Wan2.2-I2V-A14B 双专家 480p/16fps → LatentSync 1.6 → RIFE×2 → 32fps
改为：关键帧(首帧) + 台词音轨(TTS) → Wan2.2-S2V-14B 一次 → 16fps 带口型 →（RIFE×2 保留 32fps）
```
- 下载：`wan2.2_s2v_14B_fp8_scaled` + `wav2vec2_large_english_fp16`（**15.86 GiB**）；
- 工作流：照 `video_wan2_2_14B_s2v.json` 摊平成我们自己的 API 格式（沿用 `deploy/comfy/` 惯例）；
- 长镜：每 77 帧一个 chunk + Extend 子图续接（**注意首尾拼接处要按现有"段间重叠"经验处理**）；
- 版本迭代可换 pose 驱动分支（官方 `--pose_video`，唱歌/舞蹈镜）。
- **收益**：LatentSync 整段链路（含"嘴部乱码/坐标系/4 帧重叠"这些历史坑）**下线**；720p 不再是"白名单+降帧数"的拼凑。
- **代价**：输出 16fps（RIFE 保留）；S2V 是首帧+音轨驱动，长镜身份可能与定妆照漂移（用 `wv_faceid.py` 量化）。

### P2 · InfiniteTalk 做「多角色对白 + 25fps」
- 原生 **25fps** ⇒ **RIFE 可省**；支持**两个角色分别掩码 + 各自音轨**，还能**给已有视频重配音**；
- 官方支持 480P/720P，README 明确"very low VRAM"模式（`--num_persistent_param_in_dit 0`）；
- 成本 ≈19.8 GiB（要新下 Wan2.1-I2V-14B-480p 基座 + patch）；
- **要做的自动化**：从关键帧自动生成"角色掩码"（人脸检测 → 掩码），否则每个镜头都要手工 MaskEditor。

### P3（探索，不进生产）· LTX-2.3 音视频联合
- 唯一"**自己出声**"的开源路线（视频+同步音轨一次生成），也是唯一 1280 宽以上起步的；
- **但台词/音色不可控**，且许可 `other`（**需复核商用条款**）、36 GB 权重、RAM 47 GiB 会紧；
- 建议：只在"环境音/氛围片/无台词镜头"试点，不接剧集对白。

## 5. 未核实 / 风险（先说清）

1. **48G 上的耗时**：S2V/InfiniteTalk 的 720p 单镜耗时**没有官方或社区口径可直接引用** ⇒ 先跑 480p 75–81 帧基线，再按 5× 像素外推验证。
2. **身份一致性**：S2V/HuMo 是"首帧 + 音轨"驱动，长镜可能漂移；`wv_faceid.py` 可量化，但阈值要重新标定。
3. **长镜拼接**：S2V 每 77 帧、InfiniteTalk 每 81 帧分块 ⇒ 拼接处的一致性需要像现在 motion 那样处理"段间重叠"。
4. **多角色掩码**：InfiniteTalk 的手工 MaskEditor 流程要产品化（自动掩码）。
5. **许可复核项**：HuMo 上游许可（Comfy-Org 重打包页标 Apache-2.0）、LTX-2.3 的 `other` 许可、IndexTTS-2 的 bilibili 自定义许可 —— 三项都要**以官方原文复核后再决定能否进生产**。
6. **音频编码器口径**：S2V 用 `wav2vec2_large_english`（英文音频！），中文台词是否需要用 xlsr-53 / chinese-base 版本替换，**官方单卡示例里带的是 xlsr-53-english**，需实测口型质量（这是 S2V 中文场景最容易踩的坑）。
7. **RAM 47 GiB**：同时开 tts(8091)/face(8093)/talk(8094) + 16 GB 视频模型 + ComfyUI 常驻时余量薄；出片前建议重启 ComfyUI 取干净基线。
