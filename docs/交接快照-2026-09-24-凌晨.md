## 3. ⛔ 当前阻塞：GPU 盒离线（**不是我们改坏的**）

```
ssh gpu（180.127.11.169:27732）→ Connection refused
网关 http://180.127.11.169:57712/system_stats → 000
平台侧（VPS）：weaveora-api / weaveora-gpu-worker / weaveora-cloud-worker 全 active；https://sysou.com/weaveora/ → 200
```
⇒ **出图/出片暂时不可用**（任务会以 `Connection refused` 失败）。端口/IP 每次重开都会变是**常态**（历史见过十几次）。

### 盒子恢复后的清单（照顺序走）

1. **取新地址/端口**（只从平台控制台读，别猜）：平台「生成引擎配置 → GPU 服务器地址 + 端口」；
   同步三处：`~/.ssh/config` 的 `gpu`/`gpu2`/`weaveora-gpu-a14b` 三别名 → 平台页 → VPS `/etc/weaveora/weaveora-gpu-worker.env` 的 `WEAVEORA_COMFY_URL`。
   ⚠️ **平台页保存后必须回读**（历史上它把失效的旧端口洗回过）：
   `ssh root@sysou.com "sudo -u postgres psql -d weaveora -At -c \"select gpu_server_url, gpu_server_port, services from user_engine_settings where gpu_server_url is not null and gpu_server_port is not null;\""`
2. **身份判据**：`curl -s http://<GPU>:<HTTP>/system_stats | python3 -c 'import json,sys;print(json.load(sys.stdin)["system"]["argv"][0])'` **必须是 `/opt/weaveora/ComfyUI/main.py`**（系统自带那套的模型搜索路径不同 → 会"图出得来但完全不对，且不报错"）。
3. **5 端口**：`8001 / 8800 / 8091 / 8093 / 8094`（坑 34：重启后 talk 的 8094 曾丢）。`systemctl is-active weaveora-stack`。
4. **配置回读**：`bash deploy/image_variant_switch.sh verify`（应输出三条 flux2 路径 + steps=20 + ✓）。
5. **权重自检**：`bash /opt/weaveora/post_maint_check.sh | grep -E 'flux2|mistral|full_encoder|Turbo|多副本|FAIL'`（5 件字节 + 无同名多副本）。
6. **验收**：定妆照 → 关键帧 → 出片 → 再回出图。
   - 预期日志：`工作流出图：flux2_dev_edit_api.json(edit) …`、`参考槽措辞已改写`、`负词…折进正词`、**跨家族时** `需重启 ComfyUI 释放上一套` + `ComfyUI 重启完成（Ns）`；
   - 跨家族/重启后**第一次任务会多花 1–2 分钟冷加载**（这是修 OOM 的代价，不是故障）。
   - 客观身份验收：`ssh gpu "/opt/weaveora/ComfyUI/venv/bin/python /opt/weaveora/diag/wv_faceid.py --img <出图> --ref 宝玉=… --ref 可卿=… --ref 警幻=…"`

> 🔎 **排障口诀**：任务报 `Connection refused` / `502 edge proxy: Cannot connect to host 127.0.0.1:8001` 时，**先怀疑"盒离线 或 地址端口变了"**，
> 不要先怀疑 OOM —— OOM 那类已由 worker 自动重启兜住，且在日志里会先打 `需重启 ComfyUI 释放上一套`。
